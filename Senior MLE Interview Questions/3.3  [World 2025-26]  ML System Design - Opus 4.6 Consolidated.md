## 2. Core ML: From-Scratch Coding & Vectorization

### Q1: Implement K-Means from Scratch (Vectorized)
**Frequency**: Very High | **Weightage**: High (Core Round 1 gatekeeper) | **Companies**: Microsoft L63, Meta, Nvidia, OpenAI

**Expected answer points**:
- Initialize centroids using **K-Means++ (probabilistic distance-weighted sampling)** rather than naive random selection
- Formulate the iterative **E-step** (assign each point to nearest centroid via Euclidean distance) and **M-step** (recompute centroid as mean of assigned points)
- **Vectorize**: eliminate explicit Python loops using `X[:, None, :] - centroids[None, :, :]` or algebraic identity for matrix multiplication efficiency
- Handle edge cases: empty clusters (re-seed from farthest point), convergence tolerance (epsilon), chunked mini-batch processing for large tables

**Sources**: LeetCode Microsoft L63, Exponent ML Coding, HelloInterview

---

### Q2: Implement Transformer Encoder Layer - Self-Attention & Masked Multi-Head Self-Attention
**Frequency**: High | **Weightage**: Critical | **Companies**: Microsoft L63, Apple ICT4

**Expected answer points**:
- Define linear projections for Query (Q), Key (K), and Value (V) across batch size, sequence length, and hidden dimension
- Reshape and transpose tensors for h heads of dimension d_k to compute **scaled dot-product attention**: `Attention(Q,K,V) = softmax(QK^T / sqrt(d_k))V`
- Explain the **sqrt(d_k) scaling factor**: prevents dot products from growing large in magnitude for large d_k, pushing softmax into vanishing gradient regions
- For **causal masking**: apply an upper-triangular matrix filled with -inf (or -1e9) prior to softmax so future tokens receive zero probability weight

**Sources**: LeetCode Microsoft L63, InterviewQuery Apple ML

---

### Q3: Compute Mean Average Precision (mAP) for Object Detection
**Frequency**: High | **Weightage**: High | **Companies**: Nvidia, Apple, Meta, OpenAI, Anthropic

**Expected answer points**:
- Implement **IoU (Intersection over Union)** calculation between two bounding boxes
- For each class independently: sort predicted bounding boxes in descending confidence order
- Match predictions to ground-truth using IoU threshold (e.g., 0.5); mark as **TP** if exceeds threshold and GT box not already matched (greedy matching), otherwise **FP**
- Compute cumulative Precision and Recall arrays; integrate area under PR curve (11-point interpolation or all-point trapezoidal)
- Average AP across all classes for mAP

**Sources**: Exponent ML Questions

### Q4: Implement Fundamental ML Layers in Pure Python/NumPy
**Frequency**: High | **Weightage**: High (Meta "Specialist Ninja" / Google ML Coding) | **Companies**: Google L5, Meta E5, Apple ICT4, JPMorganChase

**Algorithms to implement**:
- **(a) kNN**: Pairwise Euclidean distances, top-k via `argpartition` in O(n) time, majority class vote with deterministic tie-breaking
- **(b) Logistic Regression / 2D Convolution / Batch Normalization**: For BatchNorm - track running mean/variance during training vs frozen statistics during inference; compute and scale/shift via learnable parameters (gamma, beta)
- **(c) Gradient Descent / Linear Regression**: Normal equations `w = (X^TX)^{-1}X^Ty` - address numerical instability when X^TX is singular (pseudo-inverse or L2 ridge penalty); O(n^3) complexity breakdown at scale vs iterative SGD
- **(d) Precision/Recall**: From mathematical formula
- **Multithreaded parallelization**: Partition batches across worker threads; manage Python GIL limitations, shared memory, or lock-free reductions

**Sources**: LeetCode Google L5, igotanoffer Google MLE, InterviewQuery Apple

## 3. Core ML: Classical Theory, Regularization & Tree Ensembles

### Q5: Overfitting vs Underfitting - Tree Regularization - Random Forest vs XGBoost
**Frequency**: Very High | **Weightage**: Medium-High | **Companies**: Nvidia, Apple, Databricks, Microsoft L63, JPMorganChase

**Expected answer points**:
- Overfitting = low training error but high generalization variance; unpruned Decision Trees and deep Random Forests memorize noise. Linear/logistic regression prone to underfitting (high bias) when boundaries are highly nonlinear
- **Tree regularization**: `max_depth`, `min_samples_split`, `min_samples_leaf`, `max_features` (column subsampling), cost-complexity pruning (alpha), k-fold cross-validation with diagnostic validation learning curves
- **Random Forest vs XGBoost**: RF uses parallel bagging of deep trees to reduce variance; XGBoost uses sequential gradient boosting of shallow trees via second-order Taylor expansion (Hessians) to reduce bias. XGBoost supports custom differentiable loss functions, built-in L1 (`reg_alpha`) and L2 (`reg_lambda`) leaf-weight regularization, natively handles missing values via learned default directions, and leverages histogram-based GPU acceleration (`tree_method="hist"`)

**Sources**: InterviewQuery Nvidia MLE, Exponent ML Questions, InterviewQuery Apple

---

### Q6: L1 vs L2 Regularization - MLE vs MAP - Multicollinearity - Perfect Separability
**Frequency**: Very High | **Weightage**: Medium-High | **Companies**: Google, Amazon L5, Uber, LinkedIn, Meta

**Expected answer points**:
- **Lasso (L1)** adds penalty lambda * ||w||_1 (equivalent to Laplace prior in MAP inference); constant subgradients drive redundant feature weights to exact zero - automated feature selection
- **Ridge (L2)** adds penalty lambda * ||w||_2^2 (equivalent to Gaussian prior in MAP); shrinks correlated weights proportionally without zeroing them - preferred when all features carry predictive signal
- **MLE vs MAP**: MLE maximizes P(D|theta); MAP maximizes P(theta|D) = P(D|theta)*P(theta), where P(theta) is the prior. L2 regularization is equivalent to MAP with Gaussian prior
- **Multicollinearity**: inflates variance of coefficient estimates (X^TX approaches singularity), widening confidence intervals and making individual feature attribution unstable, even though overall predictive power remains intact
- **Omitted variable bias**: excluded confounder correlating with both predictor and target biases estimated coefficients
- **Perfect linear separability**: unregularized logistic regression causes weight vector w -> infinity (parameter divergence) as model pushes predicted probabilities to exact 0 and 1; mitigation requires L1/L2 regularization, early stopping, or switching to max-margin classifier

**Sources**: LeetCode Amazon L5, igotanoffer Google Data Science, InterviewQuery Python ML, Prepfully MLE

---

### Q7: PCA - K-Means vs EM/GMMs - Clustering Evaluation
**Frequency**: Medium | **Weightage**: Medium | **Companies**: Google, LinkedIn

**Expected answer points**:
- **PCA**: Center data matrix X, compute covariance matrix (or apply SVD), project data onto top-k orthogonal eigenvectors corresponding to largest eigenvalues that maximize captured variance
- **K-Means vs GMM**: K-Means is a hard-clustering special case of EM assuming spherical clusters with identical isotropic covariance matrices. GMMs use soft probabilistic assignments (responsibilities) and learn full covariance matrices per component - applicable for ellipsoidal, overlapping, or varying-density clusters
- **Evaluation**: With ground-truth labels - extrinsic metrics (ARI, NMI, Homogeneity, Completeness). Without labels - intrinsic metrics (Silhouette Score, Davies-Bouldin Index, within-cluster SSE)

**Sources**: igotanoffer Google Data Science, Prepfully ML Engineer

## 4. Core ML: Deep Learning Mechanics, Calibration, Bandits & Drift

### Q8: Vanishing Gradients - Normalization - Reproducibility
**Frequency**: High | **Weightage**: Medium-High | **Companies**: Meta, Nvidia, Apple, OpenAI

**Expected answer points**:
- **Beginning (early) layers** are vastly more susceptible to vanishing gradients. By the chain rule of backpropagation, the gradient w.r.t. early layer weights is a product of Jacobians across all subsequent layers; when activation derivatives (sigmoid/tanh) or weight singular values are < 1, this repeated multiplication decays exponentially toward the input layers
- **Mitigations**: Residual skip connections, ReLU/GELU activations, Normalization layers (BatchNorm, LayerNorm, RMSNorm) stabilize activation distributions and gradient flow
- **Same algorithm, different results on identical data**: random weight initialization, stochastic mini-batch shuffling, dropout masks, non-deterministic CUDA atomic operations in GPU kernels, data split variations. Control via fixed seeds, deterministic cuDNN flags, and multi-run statistical comparisons

**Sources**: Exponent ML Questions, InterviewQuery Optiver MLE, Prepfully MLE

---

### Q9: Platt Scaling - Class Imbalance - Offline vs Online Metrics - Covariate/Label Shift - Off-Policy Learning
**Frequency**: High | **Weightage**: Very High (L5 differentiator) | **Companies**: Microsoft L63, Apple, Uber

**Expected answer points**:
- **Platt Scaling**: fits parametric logistic regression on top of uncalibrated model logits using a held-out validation fold
- **Class imbalance**: downsampling majority class distorts prior probabilities and shifts predicted log-odds, requiring post-hoc prior correction or Platt recalibration
- **Offline > Online performance gap**: training-serving skew, temporal data leakage, unmodeled latency timeouts, selection bias in historical logs
- **Covariate shift**: P(X) changes while P(Y|X) remains constant. **Label/prior shift**: P(Y) changes. Detection via **KS test**, **PSI**, or **KL divergence**
- **Off-policy learning**: When fitting a new model on logged data from an old policy, mitigate counterfactual selection bias using **Inverse Propensity Scoring (IPS)** - weighting samples by clipped importance ratios - or **Doubly Robust (DR) estimators**. Contrast **Bayesian Thompson Sampling** against uniform epsilon-greedy exploration

**Sources**: LeetCode Microsoft L63, InterviewQuery Apple, InterviewQuery Uber

### Q10: Production Debugging - Fraud Model Recall Drop After Data Refresh
**Frequency**: High | **Weightage**: Very High | **Companies**: Stripe, Uber

**Expected answer points**:
- No model or serving code changed -> failure originates in **upstream data contract, feature pipeline, or label ingestion**
- Root-cause hypotheses:
  1. **Schema/unit mutation**: upstream feature values changed scale or timezone alignment broke windowed aggregations
  2. **Categorical mapping / NULL explosion**: new merchant category codes or broken joins caused high-importance features to default to NULL or OOV buckets, collapsing model discrimination
  3. **Delayed/corrupted chargeback labels**: refreshing with immature recent transactions labels true fraud as negative
- **Remediation**: inspect schema changes, recompute feature distribution statistics and null rates vs historical baselines, roll back corrupted data artifact, enforce automated data-quality gatekeepers, retrain on validated subset

**Sources**: InterviewQuery Stripe MLE, InterviewQuery Uber

## 5. GenAI & LLMs: Transformer Internals, Context Scaling & Quantization

### Q11: BERT vs GPT - Bi-Encoders vs Cross-Encoders
**Frequency**: Very High | **Weightage**: High | **Companies**: Microsoft L63, Google, Avaamo Bengaluru

**Expected answer points**:
- **BERT**: Encoder-only bidirectional transformer; pretrained via **MLM** (masked language modeling - predict randomly masked tokens using full left-and-right context) and **NSP** (Next Sentence Prediction)
- **GPT**: Decoder-only causal transformer; masked self-attention to predict next token autoregressively - enables open-ended generative scaling
- **Bi-encoders**: Pass query and document independently through twin towers to produce separate dense vectors; scored via cosine similarity/dot product. Document embeddings can be precomputed and indexed in ANN - low-latency retrieval over millions of docs, but misses fine-grained token-level cross-attention
- **Cross-encoders**: Concatenate [query, document] into single transformer pass; full all-to-all cross-attention - superior relevance accuracy but cannot precompute query-dependent representations - restricted to second-stage reranking of small candidate sets

**Sources**: LeetCode Avaamo Senior MLE, LeetCode Microsoft L63, igotanoffer Google DS

---

### Q12: LLM Context Window Scaling - Decoding Strategies - Quantization Trade-offs
**Frequency**: Very High | **Weightage**: Very High | **Companies**: Anthropic, OpenAI, Nvidia, Meta, Apple

**Expected answer points**:
- Increasing context length L scales **prefill self-attention compute quadratically** O(L^2) and expands **KV-Cache memory linearly** - bottlenecks GPU HBM capacity, reduces max concurrent batch size, increases **TTFT** (Time-To-First-Token), and introduces "**lost-in-the-middle**" attention dilution
- **Decoding strategies**:
  - **Temperature** T scales logits (logit/T) prior to softmax; T->0 = greedy, T->infinity = uniform
  - **Top-k**: Truncates sampling to the k most probable tokens
  - **Top-p (nucleus)**: Dynamically selects smallest set of tokens whose cumulative probability exceeds p
  - **Beam Search**: Maintains B active sequence hypotheses to maximize global sequence likelihood
- **Post-Training Quantization (PTQ)**: FP16 -> INT8/INT4 is deterministic lossy weight compression. Rounding errors systematically shift the learned function away from full-precision optimum - **primarily increasing bias** - while quantization noise near decision boundaries across diverse prompts also **induces effective output variance**

**Sources**: Exponent ML Questions, LeetCode Avaamo

## 6. GenAI & LLMs: Fine-Tuning, Alignment & Embeddings

### Q13: Fine-Tuning Approaches - Embedding Fine-Tuning - Contrastive Learning
**Frequency**: High | **Weightage**: High | **Companies**: OpenAI, Databricks, Google, Meta

**Expected answer points**:
- **Full SFT** updates all weights - heavy optimizer state memory
- **LoRA (Low-Rank Adaptation)**: Freezes pretrained weights W0 and injects trainable low-rank matrices delta_W = BA (r << d), slashing trainable parameters. Zero-latency weight merging (W = W0 + BA) at inference
- **QLoRA**: LoRA on 4-bit quantized base model
- **RLHF / DPO**: Alignment after SFT. RLHF trains reward model + PPO; DPO directly optimizes on preference pairs without separate reward model
- **Embedding fine-tuning**: Domain-specific (anchor, positive, negative) tuples using **Triplet Margin Loss** or **contrastive InfoNCE loss** with hard-negative mining
- **Modern LLM embeddings vs classical**: Deeply contextualized sequence representations trained via large-scale contrastive objectives - capture semantic intent across entire passages (vs static word2vec/GloVe)

**Sources**: LeetCode Avaamo, InterviewQuery OpenAI MLE, InterviewQuery Databricks MLE, igotanoffer FAANG

## 7. GenAI & LLMs: Hallucination, RAG & Evaluation

### Q14: Hallucination Taxonomy - RAG Architecture - ANN Algorithms - Semantic Caching
**Frequency**: Very High | **Weightage**: Critical | **Companies**: Anthropic, OpenAI, Apple, Meta, Google

**Expected answer points**:
- **Hallucination taxonomy** (Anthropic framework):
  1. **Intrinsic**: Directly contradict provided context
  2. **Extrinsic**: Introduce unsupported facts beyond the context
  3. **Fabrications**: Confidently generated false facts or non-existent citations
- **RAG chunking strategies**: Fixed-size token splitting with sliding overlap; structure-aware recursive/header parsing; semantic chunking based on embedding similarity thresholds
- **ANN algorithms in vector databases**:
  - **HNSW**: Graph-based traversal - high recall + low latency at higher RAM cost
  - **IVF-PQ**: Inverted file lists + product quantization - memory compression
- **Production mitigation & strict source control**: Hybrid search (BM25 + vector), cross-encoder reranking, constrained decoding requiring inline citations, NLI entailment verification, semantic caching in Redis for recurring queries

**Sources**: Exponent ML Questions, InterviewQuery Apple ML, LeetCode Avaamo

### Q15: LLM & RAG Evaluation - North-Star Metrics for High-Stakes AI Agents
**Frequency**: Very High | **Weightage**: Very High | **Companies**: OpenAI, Anthropic, Google, Meta

**Expected answer points**:
- **Classical metrics**:
  - **BLEU**: n-gram precision overlap (translation) - misses semantic meaning
  - **ROUGE**: Recall-oriented surface overlap (summarization) - misses factual correctness
  - **Perplexity**: exp(-avg log prob) - intrinsic measure of token prediction confidence; only indirectly signals user-facing quality
- **RAG evaluation** separates:
  - **Retrieval metrics**: Recall@k, MRR, NDCG@k
  - **Generation metrics**: **Faithfulness / Hallucination Rate** (whether generated claims are grounded in retrieved sources) + human preference ratings
- **Healthcare/financial AI agent north-star metrics**: End-to-end task completion rate, claim adjudication accuracy, zero policy/compliance violation rate, latency/cost per resolution
- **Ethical risks**: Biased coverage denials, prompt injection, unauthorized financial actions - require deterministic policy guardrails, human-in-the-loop escalation thresholds, immutable audit trails

**Sources**: Exponent MLSD Guide, Exponent ML Questions, InterviewQuery OpenAI MLE, igotanoffer FAANG

## 10. MLSD: GenAI, Enterprise RAG & Agentic System Design

### Q23: Design End-to-End Enterprise RAG / LLM Q&A System
**Frequency**: Very High | **Weightage**: Critical (Flagship GenAI MLSD question 2025-2026) | **Companies**: Apple, Google, Meta, OpenAI, Anthropic, SAP, Zscaler

**Expected answer points**:
- **Ingestion pipeline (write-heavy)**: Decouple heavy document uploads using **Kafka** and a **saga/workflow engine** - multi-stage ingestion (extract, parse complex tables, chunk, embed, index) with async queues, exponential backoff, dead-letter handling, and idempotent retries
- **Query pipeline (read-heavy, p95 < 300-500ms)**:
  - **Redis** for semantic caching and per-tenant rate limiting
  - **Elasticsearch** (or partitioned vector DB) for **hybrid retrieval** (BM25 keyword + dense vector ANN)
  - **Cross-encoder reranking** + **grounded inline citations**
- **Multi-tenancy**: Strict access permissions via metadata pre-filtering across both ingestion and query paths
- **Monitoring**: Production Faithfulness and token cost to prevent regressions

**Sources**: HelloInterview RAG Pipeline, Prepfully Apple, Exponent ML Questions, HelloInterview

## 11. MLSD: ML Infrastructure, GPU Serving & MLOps

### Q25: Design High-Throughput GPU Inference Batching & Concurrent LLM Serving
**Frequency**: High | **Weightage**: Very High | **Companies**: Nvidia, OpenAI, Anthropic, Apple, Meta

**Expected answer points**:
- **Single-GPU synchronous inference batching** (up to 100 inputs/batch): Dynamic batching scheduler with bounded wait-time window (5-10ms); dispatches when batch reaches 100 inputs or timeout expires - maximize GPU compute utilization while respecting synchronous client wait
- **Concurrent LLM serving (/v1/chat/completions)**: Continuous iteration-level batching, KV-cache memory management, dropped-connection playback, branching conversation state
- **LLM Gateway/Proxy**: Unified routing layer between applications and LLM providers - semantic caching, rate limiting, automated provider fallbacks, cost optimization (route simple queries to cheaper models), centralized observability

### Q26: Design ML Platform Infrastructure - Distributed Training / Experiment Tracking / A/B Testing
**Frequency**: High | **Weightage**: High | **Companies**: Databricks, Stripe, Meta, Google, OpenAI

**Expected answer points**:
- **Distributed Training & LLM Fine-Tuning**: Contrast **Data Parallelism** (replicate model across GPUs, partition data) vs **Model/Tensor/Pipeline Parallelism** (shard model layers/tensors across GPUs). Detail hardware-aware sharding, checkpoint fault tolerance, and job orchestration

- **Config-Driven LLM A/B Testing**: Dynamic traffic-splitting control plane that routes configurable percentage (e.g., 10%) of live requests to new prompt/model version without code deploy - continuously evaluate multi-metric guardrails - **automatic rollback** if safety or latency degrades

## 12. Strategic Preparation Notes

> [!IMPORTANT]
> ### Anti-Downleveling Signals for L5
> 1. **Proactively introduce constraints**: Don't wait for the interviewer to prompt for latency budgets (sub-200ms for fraud, 250ms for feed ranking), unit economics, failure modes, or data drift
> 2. **Justify simpler models**: When a GBDT or bi-encoder is cheaper and more reliable than a frontier LLM, say so with cost/latency numbers
> 3. **Speak to operational depth**: Semantic caching, INT8 quantization, dynamic GPU batching, cascading architectures
> 4. **Translate domain experience**: PII/HIPAA governance -> multi-tenant RAG ACLs; clinical/financial adjudication -> calibrated cost-sensitive thresholds + human-in-the-loop agentic guardrails; offline ablation studies -> online production latency and drift validation
> 5. **Practice spoken walkthroughs**: Many MLSD interviews at Meta E5 and Google L5 use plain text editors without collaborative whiteboarding. Practice top-down architectural walkthroughs covering problem formulation -> data/feature pipelines -> two-stage modeling -> offline-to-online evaluation gaps -> serving infrastructure within a **strict 35-40 minute window**

### Time Budget for 45-Minute MLSD Round
| Phase | Duration | Focus |
|-------|----------|-------|

| Feature engineering & data pipelines | 8 min | Real-time vs batch, feature store |
| Model training & architecture | 8 min | Two-stage, multi-task, model selection justification |
| Production deployment & serving | 8 min | Latency, batching, caching, A/B, rollback |
| Evaluation & monitoring | 5 min | Offline/online gap, drift detection, guardrails |
